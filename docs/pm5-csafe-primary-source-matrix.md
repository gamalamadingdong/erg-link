# PM5 / CSAFE primary-source requirements matrix

## Purpose and audit scope

This matrix is a primary-source baseline for auditing the current ErgLink PM5 implementation. It covers:

- BLE discovery, services, characteristics, and notification subscription;
- PM5 BLE notification payload layouts, byte order, units, and validity values;
- CSAFE frame construction, byte stuffing, checksum, command/response behavior, and pacing;
- proprietary workout-programming commands and limits;
- response and error handling; and
- workout, interval, termination, and completion state.

It deliberately distinguishes two different layers:

1. **PM5 BLE rowing notifications** are direct GATT payloads from the Rowing Service (`CE060030...`), such as characteristics `0x0031`–`0x003A`. They are **not CSAFE frames**.
2. **CSAFE commands and responses over BLE** are framed CSAFE byte streams transported through the PM Control Service (`CE060020...`) using receive characteristic `0x0021` (host writes commands to the PM) and transmit characteristic `0x0022` (host reads responses from the PM).

## Source basis and citation convention

Primary sources:

- Current authority: Concept2 **Performance Monitor CSAFE Communication Definition**, revision 0.34, dated 2025-07-17 and published March 2026: <https://cms.concept2.com/sites/default/files/2026-03/Concept2%20PM%20CSAFE%20Communication%20Definition.pdf>.
- Citation baseline: `docs/concept2-pm5-reference/PM5_CSAFECommunicationDefinition.pdf`, revision 0.27, 2023-08-08. The detailed page references below use this bundled copy; the corresponding requirements were checked against revision 0.34 unless noted.
- `docs/concept2-pm5-reference/PM5_CSAFE_SPEC.md` is a repository-local text rendering of that same Concept2 definition and is cited by heading where useful for searchability.

The bundled `csafe-spec/src/csafe-spec.pdf` is byte-for-byte identical to the bundled revision 0.27 PDF (same SHA-256: `510bbbc5960050480d3b9545e276d55a7a7592e095312d019b4b5300fca9ae0b`). `csafe-spec/csafe-spec.md` is empty. It therefore supplies no separate general-CSAFE authority. This matrix does **not** infer behavior from third-party libraries, community projects, or secondary write-ups.

Revision 0.34 additionally clarifies proprietary-protocol authentication availability and adds force-curve, watt-minute, projected-work and characteristic `0x0042` updates. Those additions are summarized in `docs/pm5-csafe-conformance-audit.md`.

Implementation citations use repository paths and line ranges as inspected for this audit. Source-document citations use PDF pages and named sections/tables. Page numbers are the printed document page numbers.

### Audit labels

- **Conforms** — current implementation matches the cited requirement for the audited scope.
- **Partial** — some required behavior exists, but an important part is missing or inaccurate.
- **Gap** — required behavior is absent or contradicted.
- **Not exercised** — constants/types may exist, but the runtime path does not use the capability.
- **Not established** — the primary documents do not establish the claimed behavior; it must not be treated as a protocol requirement without another primary source or hardware evidence.

## Highest-priority audit findings

1. **CSAFE byte stuffing is absent.** Both frame builders can emit reserved bytes unescaped, including a reserved checksum byte. This violates the required `F0`–`F3` escaping rules.
2. **The race command identifier is wrong and race frames use the wrong frame type.** The implementation names `0x3E` as `CSAFE_PM_SET_RACEOPERATIONTYPE`, but the Concept2 command table defines `SET_RACEOPERATIONTYPE` as `0x1E`; `0x3E` is `SET_RACECONTROLPARAMS`. Any non-disabled race operation also requires extended addressing, but ErgLink emits a standard frame.
3. **CSAFE responses are never read or validated.** ErgLink writes `0x0021` but does not read `0x0022`, inspect the response status, wait for completion, retrieve PM error type/value after rejection, or verify response frame checksum.
4. **Variable-interval programming omits required interval identity/type commands.** The implementation does not emit `CSAFE_PM_SET_WORKOUTINTERVALCOUNT (0x18)` or `CSAFE_PM_SET_INTERVALTYPE (0x17)`, contrary to Concept2's variable-interval examples.
5. **Workout repetition count is not programmed.** The application contract accepts `repeats`, but the frame builder ignores it. The primary document also says fixed interval workouts have no defined end, so a finite repeat count is not established as part of the fixed-interval PM programming model.
6. **Workout completion is not driven from PM5 completion data.** Runtime subscriptions omit `0x0039`/`0x003A`, and `workoutState` is discarded before the public `PM5Data` callback. Upload is triggered only by externally supplied race operation value `11`, not by the PM's WorkoutEnd/WorkoutLogged state or end-of-workout summary.
7. **The stroke-state enumeration is shifted and incomplete.** PM values are 0 waiting-min-speed, 1 waiting-acceleration, 2 driving, 3 dwelling, 4 recovery; ErgLink labels 1 as drive, 2 as dwell, 3 as recovery and has no value 4.
8. **Data called “strokes” are status-notification snapshots, not protocol-defined stroke records.** The buffer appends on every `0x0031`/`0x0032`/`0x0033` notification, while the primary source defines actual stroke data on `0x0035`/`0x0036` and includes a stroke count there.

## E. CSAFE responses and error handling

| ID | Primary-source requirement | Exact primary citation | Current ErgLink evidence | Audit result / requirement for remediation |

## Items not established by the bundled primary sources

The following should remain explicitly marked as assumptions until backed by a current Concept2 primary source or repeatable PM5 hardware evidence:

1. **Advertising guarantees.** The source defines GATT services and GAP name, but not that Rowing service `0x0030` is always present in advertisements.
2. **BLE CSAFE fragmentation.** The source says control characteristic values are up to 20 bytes yet publishes longer CSAFE sample frames and larger possible ATT MTUs. It does not define a portable application-layer fragmentation protocol across writes/reads.
3. **GATT write success as command success.** The source instead defines CSAFE responses/status; a resolved BLE write alone is not proof of PM acceptance.
4. **Finite repeat counts for fixed interval workout types.** Appendix E calls them no-defined-end workouts. ErgLink's `repeats` contract is a product-level concept unless encoded via a documented variable-workout strategy.
5. **Extra `CONFIGURE_WORKOUT` for JustRow.** The proprietary JustRow sample omits it; the source does not explicitly prohibit it.
6. **Status notifications as stroke records.** The primary source defines separate stroke-data characteristics; no source basis was found for calling each `0x0031`/`0x0032`/`0x0033` callback a stroke.
7. **Unlisted payload bytes or firmware behavior.** The implementation must not assign meanings to bytes that are omitted from the audited table, nor assume newer-firmware fields exist outside the firmware ranges stated by Table 14.

## Recommended audit order

1. Fix command constants (`SET_RACEOPERATIONTYPE=0x1E`) and implement standard/extended framing plus byte stuffing and source-vector tests.
2. Add a serialized request/response channel over `0x0021`/`0x0022`, including checksum/status/error handling and the 50 ms rule.
3. Rebuild fixed-interval and variable-interval command sequences from the Concept2 examples; add parameter validation and explicit semantics for repeats.
4. Correct the stroke-state, machine-type, screen-value, and transition-state names/enumerations.
5. Separate periodic status samples from actual stroke data; subscribe to `0x0035`/`0x0036` if per-stroke records are required.
6. Expose PM workout state and subscribe to `0x0039`/`0x003A` so completion/upload is PM-driven and distinguishes natural completion from termination.
7. Resolve the 20-byte BLE control transport ambiguity against current official Concept2 documentation or controlled PM5 firmware tests before implementing any fragmentation scheme.
